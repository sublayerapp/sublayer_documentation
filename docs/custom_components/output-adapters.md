# Custom Output Adapters

Output adapters in Sublayer are powerful components that define the structure and format of the AI-generated output. They serve as a bridge between the raw AI responses and the structured data your application expects.

## The Output Adapter Interface

To create an output adapter in Sublayer, you need to implement the following interface:

**Required Properties**
- `name`: A string that provides a name for the high level information you're expecting to receive from the LLM
- `description`: A string that elaborates on what that name represents. This is also sent to the LLM to provide more context on what you're expecting to receive

**Required Methods**
- `initialize`: A method that initializes the output adapter with at least the name and description properties.
- `properties`: A method that returns a single element array of `OpenStruct` objects representing the properties of the output. Each element needs at least a `name`, `description`, and `type` property and follows JSON spec. This is used for defining the function call in the LLM.

**Optional Methods**
- `load_instance_data(generator)`: A method to load the instance data from the generator in order to be used in the output adapter. This is useful for times when you might want to pass data into a generator that would be used in the output adapter. For example, cases where you want to pass in a list of items for an LLM to select from. Used in the `StringSelectionFromList` output adapter linked below.

- `materialize_result(raw_result)`: A method that receives the raw results from the LLM and returns a transformation of it. This is useful when you want to coerce the results into a specific type, or instantiate an object with the properties you receive from the LLM. Used in the `NamedStrings` output adapter linked below.

## Using Your Custom Output Adapter

For custom output adapters, you can pass the class directly into the `llm_output_adapter` method in the Generator like so:

```ruby
class MyGenerator < Sublayer::Generators::Base
  llm_output_adapter class: MyOutputAdapter,
    name: "My Output Adapter",
    description: "This is a custom output adapter that does something special",
    custom_attribute: "This is a custom attribute that is passed to the output adapter"

  # ... rest of the generator code
end
```

## Output Adapter Types

The Sublayer framework offers a variety of built-in output adapters, each serving a unique purpose and use case. Below is a detailed explanation of the types you can leverage to output structured data effectively.

### Single Integer
A simple adapter to capture a single integer result.

**Use Case:** When you need an integer calculation or a value like a count or index.

**Example Implementation:**
```ruby
llm_output_adapter type: :single_integer,
                   name: "count",
                   description: "The count of items processed"
```

### Single String
Captures a singular string output, which is the most common use case for simple text generation.

**Use Case:** Generating a single block of text, such as a paragraph or a simple string answer.

**Example Implementation:**
```ruby
llm_output_adapter type: :single_string,
                   name: "generated_text",
                   description: "The text generated by the model"
```

### List of Strings
Collects a list of string values in an array.

**Use Case:** Useful for generating multiple lines or entries, such as a list of keywords or phrases.

**Example Implementation:**
```ruby
llm_output_adapter type: :list_of_strings,
                   name: "keywords",
                   description: "Keywords related to the topic"
```

### Named Strings
Useful for capturing multiple named string outputs that relate to different data points from the generation.

**Use Case:** Collecting various values with specific identifiers, like metadata.

**Example Implementation:**
```ruby
llm_output_adapter type: :named_strings,
                   name: "metadata",
                   description: "Metadata for the document",
                   attributes: [
                     { name: "author", description: "Name of the author" },
                     { name: "summary", description: "Brief summary of the content" }
                   ]
```

### List of Named Strings
Design for capturing an array of objects where each object is composed of named string attributes.

**Use Case:** Merging multiple structured responses, such as user profiles or records.

**Example Implementation:**
```ruby
llm_output_adapter type: :list_of_named_strings,
                   name: "user_profiles",
                   description: "A list of user profiles",
                   item_name: "profile",
                   attributes: [
                     { name: "username", description: "The user's name" },
                     { name: "join_date", description: "The date the user joined" }
                   ]
```

### String Selection from List
Allows for selecting a value from a predefined list of strings.

**Use Case:** Ideal for scenarios where the model selects an option from the provided set, like a menu choice or file path.

**Example Implementation:**
```ruby
llm_output_adapter type: :string_selection_from_list,
                   name: "file_path",
                   description: "Path to the selected file",
                   options: :list_of_files
```

These adapters justify the flexibility and specific use cases of structured output and help in streamlining the development workload by providing reusable components in the form of output adapters.
